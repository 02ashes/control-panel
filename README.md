# Control Panel

Панель с авторизацией по приглашениям, control-сессиями и чатом Socket.IO,
библиотекой сниппетов с отдельным доступом, кейсами, колесом и обучением Day 1.

## Локальный запуск

1. Установите **Node.js 24 LTS, не ниже 24.15.0**. Версия ветки записана в `.nvmrc`.
2. Подготовьте отдельную PostgreSQL для разработки. Не используйте рабочую базу для тестирования изменений.
3. Выполните `npm ci`.
4. Скопируйте `.env.example` в `.env`, заполните подключение и замените пример `MASTER_INVITE_CODE` собственным длинным случайным секретом.
5. Выполните `npm start`; панель находится на `http://localhost:3000/admin`.

`npm start` загружает `.env` штатным парсером Node. Уже заданные переменные процесса
имеют приоритет. `npm run dev` запускает перезапуск при изменениях.
На Windows можно использовать `START.bat` из любой текущей папки.

При первом запуске таблицы и совместимые дополнения схемы создаются до открытия
HTTP-порта. Для первого администратора зарегистрируйте зарезервированный ник
`02ashes` с мастер-кодом. Обычное приглашение не позволяет занять этот ник.
Пустой мастер-код отключает регистрацию по нему; существующие одноразовые
приглашения продолжают работать. Не передавайте мастер-код рядовым пользователям.

## Настройки

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | Подключение PostgreSQL; в рабочей среде задаётся в секретах хостинга |
| `DATABASE_SSL` | `disable`, `require` или `verify-full` |
| `MASTER_INVITE_CODE` | Секрет первичной регистрации администратора |
| `PORT` | HTTP-порт, по умолчанию 3000 |
| `NODE_ENV` | `development` локально, `production` на хостинге |
| `XAI_API_KEY` | Ключ реальной проверки Day 1; не нужен тестам |
| `TRAINING_DAY1_ENABLED` | `0` отключает Day 1 |
| `DAY1_GROK_CONCURRENCY` | Число одновременных проверок, по умолчанию 2 |
| `DAY1_GROK_QUEUE_LIMIT` | Лимит очереди, по умолчанию 20 |
| `XAI_TIMEOUT_MS` | Таймаут запроса грейдера, по умолчанию 60000 мс |

Если `DATABASE_SSL` не задан, сохранено прежнее поведение подключения: локально
без TLS, при `NODE_ENV=production` — TLS без проверки сертификата. Для публичной
БД предпочтителен `verify-full`; проверьте цепочку сертификатов вашего провайдера.
Не переносите `DATABASE_SSL=disable` из локального примера в публичное подключение.
Параметры SSL внутри `DATABASE_URL` также могут влиять на настройки драйвера pg.
Сервер работает в UTC: старые колонки `TIMESTAMP` интерпретируются как UTC,
поэтому срок cookie/control-ссылки не зависит от часового пояса компьютера.
Если старая установка записывала локальное время в эти колонки, перед переходом
отдельно проверьте и нормализуйте её данные; автоматического сдвига старых записей нет.

## Проверки без доступа к рабочим данным

```sh
npm run check
npm test
npm run eval:day1
npm audit
```

- `check` разбирает JavaScript-файлы и исполняемые inline-скрипты HTML, не запуская приложение.
- `test` проверяет роли, приватность Socket.IO, приглашения, транзакции, очистку,
  конфликты редактора, сохранение черновиков и состояния обучения.
- Интеграционные тесты запускают настоящий `server.js` с временной PostgreSQL
  в памяти через **PGlite**, подменённым драйвером и HTTP только на `127.0.0.1`.
  Они не читают `.env`, не используют реальную БД и не вызывают платный грейдер.
- PGlite проверяет SQL и транзакции, но не заменяет нагрузочные и сетевые испытания
  отдельной PostgreSQL. Его адаптер в тестах сериализует подключения.
- `eval:day1` проверяет набор примеров без сетевых запросов.
- **`eval:day1:live` — платная проверка через xAI**, запускать только намеренно.

GitHub Actions выполняет установку из lock-файла, синтаксические проверки, тесты,
сухую проверку примеров и аудит production-зависимостей. Для этих проверок секреты не нужны.
В `overrides` временно закреплена исправленная ветка `qs >=6.16.0`: Express 4 и
body-parser ограничивают её старой минорной версией. После обновления этих пакетов
override можно убрать, повторив аудит и тесты.

Редактор использует закреплённую Quill 2.0.3. Для этой версии известна
[GHSA-v3m3-f69x-jf25](https://github.com/advisories/GHSA-v3m3-f69x-jf25),
уязвимость низкой степени в экспорте HTML; исправленная версия в advisory
не указана. Поэтому `npm audit` не является полностью чистым. В этой интеграции
нет экспорта/сохранения HTML: копирование и вырезание передают только обычный текст,
сервер разрешает только текстовые операции Delta и ограниченный список оформления,
а изображения, видео, формулы, ссылки и другие вложения запрещены. Эти ограничения
сужают используемую поверхность, но не означают исправления самой зависимости.
При обновлении Quill отдельно перепроверьте advisory, clipboard и серверную валидацию.

## Роль «Сниппеты»

«Сниппеты» — дополнительное разрешение, независимое от основной роли
(`admin`, `user`, `reader`, `new`). Выдать и отозвать его может только владелец
`02ashes` в разделе управления пользователями. У владельца доступ есть всегда.
Обычная роль `admin` сама по себе не открывает сниппеты и не позволяет выдавать
это разрешение — ни себе, ни другим. Изменение основной роли не выдаёт разрешение.

По умолчанию доступ закрыт всем, кроме владельца: это относится и к новым аккаунтам,
и к существующим после обновления. Аккаунт с основной ролью `new` не получает
доступ к библиотеке даже при сохранённой отметке дополнительного разрешения.
Для остальных ролей после явной выдачи доступны просмотр и копирование;
`reader` по-прежнему не может редактировать, а `user` и `admin` могут.

Без разрешения скрыты панель, кнопки и раздел журнала сниппетов; сервер также
запрещает получение библиотеки, её сохранение и получение истории изменений.
Журнал изменений требует одновременно основную роль `admin` и доступ к сниппетам.
Обновления библиотеки через Socket.IO получают только допущенные аккаунты.
Отзыв роли очищает открытые редакторы и кэш журнала во всех подключённых вкладках;
после переподключения права заново подтверждаются сервером. Уже скопированный
или ранее экспортированный пользователем текст отозвать невозможно.

При запуске сервер добавляет `user_registrations.snippets_access BOOLEAN NOT NULL
DEFAULT FALSE`. Сами сниппеты и история изменений не удаляются и не переписываются.
После развёртывания `02ashes` должен явно выдать доступ нужным сотрудникам.
Разверните сервер и интерфейс вместе и обновите старые вкладки.

## Сохранение и доступ

- Роль определяется серверной cookie-сессией. `X-Nickname` не является удостоверением личности.
- Гости control-ссылок не получают библиотеку сниппетов и присутствие сотрудников.
- Библиотека имеет серверную `revision`. Полная запись требует `baseRevision`;
  устаревшая версия возвращает 409 вместе с актуальным снимком.
- Сохранение учитывает оформление вместе с текстом: устаревшая вкладка не может
  затереть более новое выделение только потому, что обычный текст совпал.
- Редактор объединяет независимые изменения. При конфликте одного поля сохраняет
  локальный текст в открытом редакторе и предлагает выбор версии, повтор или экспорт.
  Экспортируйте несохранённый текст перед намеренным закрытием страницы: это не
  офлайн-хранилище, сохраняющее черновики сниппетов после закрытия браузера.
- Control-ссылки загружаются с сервера только для текущего владельца. Старый общий
  браузерный кэш ссылок не используется.
- Списание кейса и начисление приза — одна транзакция. Повтор запроса возвращает
  сохранённый результат, не разыгрывая второй приз.
- Коды колеса хранятся в PostgreSQL. Повтор подтверждения того же результата
  безопасен; повторный запуск использованного кода запрещён.
- Удаление аккаунта отзывает его авторизацию и control-ссылки, удаляет личные
  результаты обучения и кейсов. Поколение сброса сохраняется как технический
  маркер, чтобы поздние запросы не восстановили данные при повторном использовании ника.

## Развёртывание и обновление

Проверяемая конфигурация проекта рассчитана на **один постоянно работающий Node-процесс**
и PostgreSQL; в репозитории есть настройки Railway. Старый `vercel.json` сохранён,
но его развёртывание этой редакцией не проверялось — не считайте его проверенной
альтернативой без отдельного испытания Socket.IO и жизненного цикла процесса.

В `railway.json` выбран сборщик **Railpack**, а `engines.node` ограничен веткой
Node.js 24 LTS (не ниже 24.15.0), как и локальная/CI-конфигурация. Если в Railway
задана переменная `RAILPACK_NODE_VERSION`, она имеет приоритет: удалите старое
переопределение либо задайте совместимую версию 24.15.0 или новее в ветке 24.
Порядок выбора версии описан в [документации Railpack](https://railpack.com/languages/node/).

Перед обновлением рабочей среды:

1. Сделайте резервную копию PostgreSQL средствами провайдера.
2. Проверьте установку и запуск новой версии на отдельной базе/копии без реальных пользователей.
3. Проверьте Node, секреты, TLS к БД и доступность грейдера, если он используется.
4. Разверните сервер и клиент вместе; старые вкладки редактора необходимо обновить
   из-за нового контракта сохранения с `baseRevision`.
5. Проверьте `/readyz`, вход, роли, создание control-ссылки, сохранение сниппета и обучение.

Изменения схемы этой редакции добавляют таблицу `wheel_codes` и `result_json` для
сохранённых результатов кейсов; существующие результаты не удаляются. Для старого
кейса без сохранённого результата повторное открытие по-прежнему запрещено.
Неиспользованные коды колеса, созданные старым процессом только в памяти,
пережить его первое обновление не могут — при необходимости перевыпустите их.
Первичное заполнение призов теперь транзакционно. Если старая установка уже
успела сохранить неполный набор до сбоя, проверьте его в админке: автоматически
заменять существующие настройки призов стандартным набором сервер не будет.

`/healthz` проверяет жизнь процесса, `/readyz` — доступность базы. Railway использует
`/readyz` перед переключением трафика. При SIGTERM/SIGINT сервер закрывает подключения,
останавливает фоновые таймеры и освобождает пул; предельное ожидание — 30 секунд.

Не включайте несколько реплик без отдельной доработки: комнаты Socket.IO,
online-список, кэш control-сессий и ограничения частоты остаются локальными процессу.
Для нескольких реплик нужны общий Socket.IO adapter/шина событий, согласованная
инвалидация сессий, общий rate limit и проверенная стратегия фоновых задач.

## Структура

### Рабочий интерфейс

По умолчанию используется графитовая тема. Кнопка «Светлая тема» переключает палитру
и сохраняет выбор только в текущем браузере; он применяется ко всем рабочим разделам.
Для аккаунтов с ролью «Сниппеты» библиотека остаётся слева: папки, открытые вкладки
и текст доступны одновременно с чатом.
Кнопка «Копировать» даёт короткое подтверждение рядом с редактором, без звука.
Ширину редактора можно менять перетаскиванием правого разделителя либо стрелками
влево/вправо после перехода к нему клавишей Tab. Home/End задают допустимые пределы.
При узком экране сниппеты и чат располагаются друг над другом, чтобы оба оставались
доступны. Выбор темы и ширина панели не содержат текстов переписки или сниппетов.

### Порядок вкладок и библиотеки

Верхние вкладки можно перетаскивать за название: линия показывает место вставки.
После фокусировки вкладки клавишей Tab сочетание Alt + ← / → сдвигает её на одну
позицию. Открытые вкладки, их порядок и активная вкладка сохраняются **лично для
аккаунта в этом браузере** и восстанавливаются после обновления страницы, только
после проверки доступа и загрузки библиотеки. В локальном хранилище только ID,
без названий и содержимого; отзыв доступа очищает загруженное состояние вкладок.

Слева перетаскивайте названия сниппетов и папок **внутри одного уровня**; перенос
в другую папку этим жестом не выполняется. Alt + ↑ / ↓ или меню `↕` → «Выше» /
«Ниже» дают тот же результат, в том числе без мыши. В меню папки доступны сортировки
«По названию: А–Я» и «По названию: Я–А». Кнопка «Порядок» над деревом сортирует
корневой список. Сортировка учитывает числа: «Блок 2» идёт перед «Блок 10»;
это разовая перестановка, после неё можно вручную менять порядок.

Порядок библиотеки **общий для всех допущенных пользователей** и автоматически
сохраняется на сервере; менять его могут `admin`/`user` с доступом к сниппетам.
Допущенный `reader` переставляет только свои вкладки, но не общую библиотеку.
Оформление, текст и черновик чата при перестановке не меняются. Одновременные
изменения разных папок объединяются; несовместимые перестановки одного списка
показывают конфликт вместо незаметного перезаписывания коллеги.

В JSON порядок корня хранится в `structure`, а папка может содержать `order` —
массив ID своих непосредственных детей. Старые библиотеки без `order` совместимы;
дети, которых нет в сохранённом порядке, добавляются в конец. Экспорт и импорт
сохраняют этот порядок. Новая таблица или миграция базы для него не требуется.

### Форматирование сниппетов

Панель над текстом позволяет выделять фрагменты жирным, курсивом, подчёркиванием
или зачёркиванием, менять цвет букв и фон выделения, а также очищать оформление.
Оформление сохраняется в том же сниппете; вкладки, папки и копирование остаются
слева рядом с рабочей сессией. Кнопка «Копировать», обычное копирование выделения
и вырезание отправляют в буфер **простой текст**, без HTML, цветов и служебного
переноса строки редактора. Вставка из форматированных источников очищается до
текста и поддерживаемых inline-стилей; исходный HTML не хранится.

Формат файлов библиотеки сохраняет прежние `folders`, `snippets`, `structure`,
а у сниппета обязательное поле `content` по-прежнему содержит точный обычный текст.
Старые библиотеки без оформления импортируются без преобразования их текста.
У оформленного сниппета добавляется необязательное поле `richText` — текстовый
Quill Delta вида `{ "ops": [...] }`. В нём разрешены только строковые `insert`
и inline-атрибуты `bold`, `italic`, `underline`, `strike`, `color`, `background`.
Последний перенос строки Delta служебный; он не добавляется к `content`.
Экспорт/повторный импорт новой библиотеки сохраняет и текст, и оформление.
При открытии старого текста исходные CRLF/CR не переписываются; после реального
редактирования переводы строк сохраняются как LF, без потери видимых строк.
HTML вместо Delta, объекты-вложения и неподдерживаемые атрибуты сервер отклоняет;
угловые скобки в обычном `content` остаются буквальным текстом, а не разметкой.

Изменение только оформления тоже попадает в журнал: описание явно отмечает,
что текст не менялся, а поля старого/нового содержимого остаются обычным текстом.
Новых прав редактор не выдаёт: разрешение «Сниппеты» по-прежнему управляется
только `02ashes`, а допущенный `reader` может смотреть и копировать, но не изменять.

Quill загружается локально через два явных маршрута `/vendor/quill.js` и
`/vendor/quill.core.css`, без CDN и без открытой раздачи `node_modules`.
Исходники пакетов, соседние карты исходников и другие файлы зависимостей
этими маршрутами не публикуются.

Общая палитра и переключение: `public/workspace-theme.css` / `public/workspace-theme.js`.
Компоновка основной панели: `public/panel.css`. Внешняя страница управления
`control.html` в этой итерации визуально не менялась.

- `server.js` — HTTP/Socket.IO, авторизация, инициализация схемы, обучение.
- `lib/backend-state.js` — проверяемые отдельно операции с транзакциями и правами.
- `public/snippets-sync.js` — чистая логика трёхстороннего объединения редактора.
- `public/snippets-richtext.js` — общая модель и проверка текстового Delta.
- `public/snippet-editor.js` / `public/snippet-editor.css` — безопасный адаптер Quill и его оформление.
- `index.html`, `logs.html`, `cases.html`, `control.html`, `wheel.html` — интерфейсы.
- `learn/` — Day 1, грейдер, preview и тесты.
- `tests/` — DOM-регрессии и интеграционные проверки приложения/SQL.

Новые серверные файлы не становятся публичными автоматически: HTTP раздаёт
только явно разрешённые страницы, файлы и каталоги ресурсов.
